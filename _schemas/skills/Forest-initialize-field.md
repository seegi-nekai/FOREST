# Skill: Forest-initialize-field

Создай новое поле в vault или преврати существующую папку в поле. Используй инструкцию ниже, не читай другие правила-файлы во время прохода.

## Вход

По умолчанию скилл запускается без аргументов и спрашивает имя поля интерактивно. Опционально пользователь может передать имя поля сразу.

## Область чтения и записи

Разрешено:
- читать корневой `INDEX.md`;
- читать `_schemas/templates/template-field.md` как справочник;
- читать `log.md` в корне vault;
- создавать новые папки и файлы в указанном месте vault;
- редактировать `INDEX.md` и `log.md`.

Не редактировать содержимое существующих evergreens, observations, reflections.

## Шаг 0. Сбор параметров

Если имя поля не передано — спроси:
> Имя нового поля? (например: `health`, `finances`, `business/sales`)

Имя поля совпадает с именем директории. Допустимы строчные буквы, цифры, дефисы; пробелы заменяй на дефисы. Если в имени есть `/` — слева от него имя контейнера (родительской папки).

Спроси дополнительно:
> Короткое описание поля (1–2 предложения, что в нём живёт)?
>
> Будет ли это поле выезжать в свой git-репозиторий? (по умолчанию нет)

## Шаг 1. Проверка существования

Загляни в указанный путь относительно корня vault.

- **Папки нет** — создавай с нуля (шаг 2).
- **Папка есть, но пустая или содержит произвольное содержимое** — спроси:
  > Папка `<path>` уже существует. Превратить её в поле FOREST (создать недостающие подпапки и `FIELD.md`)? Существующие файлы останутся на месте.
- **Папка уже является полем (есть `FIELD.md`)** — сообщи и заверши работу:
  > Папка `<path>` уже зарегистрирована как поле. Если нужно обновить frontmatter — открой `FIELD.md` напрямую.

## Шаг 2. Создание структуры

Если в имени есть `/` (контейнер) — убедись, что родительская папка существует. Если нет — создай её как обычную директорию **без `FIELD.md`**: это контейнер, а не поле.

В целевой папке создай подпапки, если их ещё нет:
- `observations/`
- `evergreens/`
- `reflections/`

## Шаг 3. Создание `FIELD.md`

Создай `FIELD.md` в корне поля по шаблону `_schemas/templates/template-field.md`. Frontmatter:

```yaml
type: field
name: <имя-поля>
status: active
parent: <имя-контейнера или пусто>
created: YYYY-MM-DD
updated: YYYY-MM-DD
git: <true | false>
```

Тело:
- H1 = название поля (читаемое, может отличаться от `name:` регистром и пробелами).
- Раздел «Сюда относится» — заполни на основе описания, полученного от пользователя.
- Раздел «Сюда НЕ относится» — оставь как заглушку, если пользователь не уточнил.
- Раздел «Особые правила для модели» удали, если не задавали.

## Шаг 4. Регистрация в `INDEX.md`

Открой корневой `INDEX.md`. Найди раздел `## Fields` (или создай его, если нет). Добавь запись:

```
- [[<имя-поля>/FIELD]] — <короткое описание из шага 0>
```

Если поле в контейнере — отображай путь:

```
- [[<контейнер>/<имя-поля>/FIELD]] — <описание>
```

## Шаг 5. Логирование

Открой `log.md` в корне vault и добавь в конец запись по конвенции из `CLAUDE.md`:

```
## [YYYY-MM-DD] init | <имя-поля>
```

Под заголовком — маркированный список:
- какие папки созданы;
- создан ли контейнер (если поле вложено);
- создан ли `FIELD.md`;
- зарегистрировано ли поле в `INDEX.md`.

## Шаг 6. Финальная сверка

Перед завершением убедись:
- `<path>/FIELD.md` существует и имеет корректный frontmatter;
- внутри поля есть `observations/`, `evergreens/`, `reflections/`;
- если поле в контейнере — родительская папка существует и не содержит `FIELD.md`;
- запись в `INDEX.md` добавлена;
- запись в `log.md` добавлена.

Сообщи пользователю:
> Поле `<имя-поля>` готово: `<path>/`. Что дальше — добавить источник в `observations/` и запустить `Forest-process-observation`, или сразу создать рефлексию через `Forest-reflection`?
