# Skill: process-observation

Найди новые источники в `observations/` и интегрируй каждый в evergreens соответствующего поля плюс кросс-полевые связи. Используй инструкцию ниже, не читай другие правила-файлы во время прохода.

## Вход

По умолчанию скилл запускается без аргументов и сам определяет, что обрабатывать. Опционально пользователь может передать имя конкретного файла-источника или имя поля.

## Область чтения

Разрешено:
- сырые документы в `observations/` любого поля vault;
- evergreens любого поля vault (нужно для детекта необработанных + для кросс-полевых связей);
- корневая папка `trails/` (нужно, чтобы свериться с существующими тропами);
- корневой `INDEX.md` (только на шаге обновления архитектуры);
- корневой `log.md` (только на шаге логирования);
- `_schemas/templates/template-evergreen.md` и `_schemas/templates/template-observation.md` — как справочник по frontmatter, не для редактирования.

Не читать: `reflections/`, прочие `_schemas/`, `README.md`, `FIELD.md` отдельных полей, `CLAUDE.md` и любые конфиги. Если возникает соблазн заглянуть за пределы разрешённого — остановись и спроси пользователя.

## Шаг 0. Поиск необработанных источников и формирование очереди

Определи область сканирования:
- Если передано имя файла — обрабатывается только он, шаг 0 пропускается, переходи к шагу 1.
- Если передано имя поля — сканируется `<field>/observations/`.
- Если ничего не передано — сканируются `observations/` всех полей vault.

Для каждого файла в области сравни его имя со значениями `sources:` всех evergreens соответствующего поля. Файл **необработан**, если ни одна evergreen не ссылается на него в `sources:`.

Сформируй список необработанных источников:

- **Список пуст** — сообщи: «Все источники в `<scope>` уже интегрированы» и заверши работу.
- **Один файл** — переходи к шагу 1.
- **Несколько файлов** — выведи список и спроси подтверждения:
  > Найдено N необработанных источников:
  > - `<field-1>/observations/<file-1>.md`
  > - `<field-2>/observations/<file-2>.md>`
  > - …
  >
  > Обрабатывать всё подряд или выбрать конкретные?

После подтверждения обрабатывай источники последовательно: по каждому полный цикл шагов 1–11, затем следующий. Перед каждым файлом сообщай: «Обрабатываю `<field>/observations/<file>.md` (N из M)».

## Шаг 1. Проверка captured-источника

Исходный документ должен лежать в `<field>/observations/` и иметь во frontmatter `type: observation`. Если frontmatter отсутствует или не соответствует шаблону `template-observation.md` — приведи frontmatter к шаблону, тело файла не трогай.

Папка `observations/` неизменяема в части тела. Только frontmatter может быть нормализован.

## Шаг 2. Глубокий анализ

Прочитай исходный документ. Выдели ключевые идеи, сущности, факты и аргументы. Сформируй понимание, как этот материал ложится поверх существующих evergreens поля.

## Шаг 3. Структура выжимки — подтверждение от пользователя

Реши, какая форма выжимки лучше:

- **Одна выжимка** — если идея цельная и не распадается на самостоятельные концепты:
  > Для этого источника достаточно одной выжимки. Будет создан файл: `<field>/evergreens/<имя>.md`. Создавать?

- **Несколько концептов из одного родителя** — если внутри источника явно живут несколько самостоятельных тем:
  > Источник раскладывается на N концептов. Будут созданы файлы:
  > - `<field>/evergreens/<имя-родителя>.md` — <одной строкой о чём>
  > - `<field>/evergreens/<имя-концепта-1>.md` — <одной строкой о чём>
  > - `<field>/evergreens/<имя-концепта-2>.md` — <одной строкой о чём>
  >
  > Создавать?

Без явного подтверждения дальше не идти.

## Шаг 4. Создание выжимки

Создай файл(ы) в `<field>/evergreens/` по шаблону `_schemas/templates/template-evergreen.md`. Frontmatter:

```yaml
type: evergreen
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - "[[<имя файла-источника без расширения>]]"
tags:
  - <тег>
```

Тело:
- Плотная выжимка фактов и идей собственными словами, без воды.
- H1 не используется (заголовок задаётся именем файла), вся разметка с H2.
- Никаких разделов «Связи» / «Related» / «См. также» в конце файла. Все связи — инлайн в прозе.

## Шаг 5. Горизонтальная интеграция

Просканируй `<field>/evergreens/` на связанные страницы. Внеси изменения в 5–15 релевантных заметок (если страниц в поле меньше — во все доступные):

- Впиши новые факты в существующий контекст так, чтобы они звучали органично, а не пристройкой.
- Все связи живут инлайн в прозе.
- Формат wiki-ссылок:
  - текст в заметке отличается от имени страницы → алиас: `[[Название страницы|текст в заметке]]`;
  - текст совпадает с именем страницы → простая ссылка: `[[Название страницы]]`.
- Разрешение конфликтов: если новые данные противоречат существующим, не стирай старое — явно опиши противоречие со ссылкой на оба источника.

При обновлении любой существующей evergreen:
- добавь ссылку на новый файл-источник в `sources:`;
- обнови `updated:` на сегодняшнюю дату.

## Шаг 6. Связи «родитель — потомок»

Если на шаге 3 источник разложен на родитель + потомков:
- в родительской странице упомяни в прозе каждый дочерний концепт через инлайн-ссылку;
- в каждой дочерней странице упомяни в прозе, что она — часть более широкой темы, заданной в родительском файле.

Это единственное исключение из запрета на «оглавление связей» — указание остаётся в прозе, не в отдельной секции.

## Шаг 7. Кросс-полевые связи и тропы

Проверь evergreens в других полях vault: есть ли там страницы по близким темам.

- Если найдены сильные связи — добавь wiki-ссылку инлайн в прозе новой выжимки и в соответствующих страницах других полей (с обновлением их `updated:`).
- Если по теме существует тропа в корневой `trails/` — добавь новую evergreen в её `evergreens:` и обнови `updated:` тропы.
- Если по теме копится 5+ кросс-полевых evergreens, но тропы ещё нет — предложи пользователю завести её:
  > По теме «<тема>» накопилось <N> кросс-полевых evergreens в полях <list>. Завести тропу `trails/<имя>.md`?

Без подтверждения тропу не создавай.

## Шаг 8. Язык

Не используй англицизмы. Заменяй на русские термины. Исключения: устоявшиеся выражения, собственные имена, технические идентификаторы (LLM, RAG, имена файлов и продуктов), оригинальные цитаты на английском.

## Шаг 9. Обновление архитектуры

- Открой корневой `INDEX.md` (или `index.md`) vault. Добавь новые evergreens в соответствующие разделы с однострочной аннотацией. Источник тоже добавь в раздел Sources.
- Если затронута тропа — обнови описание тропы в индексе, если она там зарегистрирована.

## Шаг 10. Логирование

Открой `log.md` в корне vault и добавь в конец запись по конвенции из `CLAUDE.md` (раздел «Логирование»). Заголовок:

```
## [YYYY-MM-DD] ingest | <Название источника>
```

Под заголовком — маркированный список всех затронутых файлов с краткой сутью изменений.

## Шаг 11. Финальная сверка

Перед переходом к следующему источнику в очереди (или завершением работы) убедись:
- frontmatter новых evergreens соответствует шаблону;
- `updated:` обновлён на всех изменённых страницах;
- `sources:` корректно ссылается на файл-источник;
- ни в одной странице не появился раздел «Связи»/«Related»/«См. также»;
- запись в `log.md` добавлена.

Если в очереди остались источники — возвращайся к шагу 1 для следующего. Если очередь пуста — сообщи пользователю сводку: сколько источников обработано, сколько evergreens создано/обновлено, какие тропы затронуты.
