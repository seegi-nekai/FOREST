# FOREST

> Земную жизнь пройдя до половины, я очутился в сумрачном лесу.
> — Данте Алигьери, «Божественная комедия»

Фреймворк для процесса мышления и накопления знаний поверх любого vault на файловой системе (Obsidian, plain Markdown). FOREST задаёт структуру папок, правила содержимого слоёв и набор скиллов, через которые языковая модель помогает накапливать, переписывать и связывать знание между сессиями.

## Для кого

- Накапливают материалы по нескольким темам жизни (работа, здоровье, финансы, исследования) годами.
- Хотят, чтобы языковая модель работала на их компилированном знании, а не на открытом вебе.
- Нуждаются в том, чтобы модель помнила между сессиями: что было решено, что попробовано, что сейчас в работе.

## На что опирается

FOREST не претендует на новизну подхода. Каждый элемент взят из накопленных школ управления личным знанием:

- **`sources → wiki → query`** — паттерн Андрея Карпатого с операциями ingest / query / lint.
- **Атомарные постоянные заметки** — метод смарт-заметок Зёнке Аренса (Цеттелькастен по Луману).
- **Различение проектов и областей** — PARA Тьяго Форте; организация по действенности.
- **Ассоциативные тропы** — мемекс Вэнивара Буша (1945) как первоклассный объект знания.

Подробное описание происхождения каждого элемента и того, чем FOREST дополняет предшественников, — в `reflections/2026-05-28 FOREST как фреймворк мышления.md`.

## Акроним

| Буква | Элемент | Что это |
|-------|---------|---------|
| **F** | Fields | Поля действий — долгоиграющие темы жизни, директории верхнего уровня |
| **O** | Observations | Источники — внешние материалы, неизменяемый слой |
| **R** | Reflections | Слепки понимания, решения, проекты — субъективный слой автора |
| **E** | Evergreens | Атомарные нейтральные знания — компилируемая вики |
| **S** | Schema | Кодекс правил для модели и человека |
| **T** | Trails | Курируемые тропы — карты по кросс-полевым темам |

## Структура vault

```
<vault>/
├── CLAUDE.md             ← глобальные правила для модели
├── INDEX.md              ← навигационный каталог
├── log.md                ← журнал операций
├── _trails/               ← кросс-полевые тропы (на уровне vault)
├── _schemas/
│   ├── skills/           ← инструкции скиллов (process-observation, initialize-field, reflection, lint)
│   └── templates/        ← шаблоны frontmatter и тел заметок
├── <field-1>/
│   ├── FIELD.md
│   ├── observations/
│   ├── evergreens/
│   └── reflections/
├── <container>/
│   ├── <field-2>/
│   │   └── ...
│   └── <field-3>/
│       └── ...
└── ...
```

## Базовые принципы

**Поле — единица организации.** Поле — это директория с маркером `FIELD.md`. Внутри — три обязательные подпапки: `observations/`, `evergreens/`, `reflections/`. Поля долгоиграющие; закрытое поле уезжает в `_archive/`.

**Контейнеры — это просто папки.** Если одно направление дробится на несколько полей (бизнес → продажи, маркетинг), родительская папка становится контейнером — обычной директорией без `FIELD.md`.

**Источники неизменяемы.** Всё, что лежит в `observations/`, — источник. Модель его читает, но не редактирует и не переписывает. Связь компилированного знания с первоисточником сохраняется аудируемой.

**Одна evergreen — одна идея.** Если одна и та же идея встречается у пяти авторов, она становится одной evergreen с пятью ссылками в `sources:`, а не пятью отдельными заметками. Это делает консенсус и новизну видимыми.

**Связи живут инлайн.** Никаких разделов «Связи»/«Related»/«См. также» в конце страниц. Все wiki-ссылки встроены в прозу.

**Поле — единица git-обмена.** Каждое поле самодостаточно и может выезжать в свой репозиторий для совместной работы. Schema vault при этом остаётся на уровне получателя.

**Тропы — на уровне vault.** Тропа собирает evergreens разных полей под общим вопросом и живёт в корневой `_trails/`. Создаётся, когда по теме копится 5+ кросс-полевых заметок и LLM нужна компактная карта вместо обхода всех файлов.

## Скиллы

- **`process-observation`** — сканирует `observations/` всех полей на новые источники, интегрирует каждый в evergreens + кросс-полевые ссылки.
- **`initialize-field`** — создаёт новое поле или превращает существующую папку в поле; регистрирует в `INDEX.md`.
- **`reflection`** — берёт пользовательский текст или транскрипцию, заземляет на evergreens поля, ищет кросс-полевые пересечения, создаёт файл reflection.
- **`lint`** — проход по vault на структурную целостность: битые ссылки, дубли, осиротевшие заметки, расхождения между слоями. Три уровня действий: auto-fix, ask, report.

Полные инструкции — в `_schemas/skills/`. Глобальные правила, на которые ссылаются скиллы, — в корневом `CLAUDE.md`.
