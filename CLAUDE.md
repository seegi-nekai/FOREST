# CLAUDE.md — глобальные правила vault

Файл правил, по которым модель работает в этом vault. Лежит в корне vault и читается перед любым другим действием. Скиллы (`Forest-process-observation`, `Forest-initialize-field`, `Forest-reflection`, `Forest-lint`) ссылаются на разделы этого документа.

## Структура vault

Корень vault содержит:

- **Поля и контейнеры** (директории). Поле помечено файлом `FIELD.md`; контейнер — обычная папка без `FIELD.md`, группирующая поля.
- **`_trails/`** — корневая папка с курируемыми тропами для кросс-полевых тем.
- **`_schemas/`** — шаблоны и тексты скиллов (`templates/`, `skills/`).
- **`INDEX.md`** — навигационный каталог: поля, evergreens, источники, тропы.
- **`log.md`** — хронологический append-only журнал операций.
- **`CLAUDE.md`** — этот файл.

Внутри каждого поля:

```
<field>/
├── FIELD.md          ← маркер поля
├── observations/     ← источники (sources у Карпатого), неизменяемы
├── evergreens/       ← атомарные нейтральные знания, переписанные собственными словами
└── reflections/      ← субъективные слепки, решения, проекты
```

## Правила по слоям

**Observations.** Сырые источники. После captured тело не редактируется. Только frontmatter может быть нормализован (см. `_schemas/templates/template-observation.md`). Папка `observations/` — read-only для всех операций кроме `Forest-process-observation`, и даже там тело остаётся как есть.

**Evergreens.** Атомарные нейтральные заметки, одна идея на страницу. Если идея встретилась у нескольких авторов — одна страница, несколько ссылок в `sources:`. Никаких разделов «Связи»/«Related»/«См. также» в конце файла; все связи — инлайн в прозе через `[[wikilink]]` или `[[wikilink|алиас]]`. `created:` ставится один раз; `updated:` обновляется при любом существенном изменении.

**Reflections.** Субъективны и привязаны к моменту. Виды: `slepok` (срез понимания + план), `decision` (фиксация выбора), `project` (конечное дело). Слепки и решения не правятся после создания; новое — новый файл с новой датой. Имя файла слепка: `YYYY-MM-DD <тема>.md`. Имя файла проекта: `<имя-проекта>.md` (без даты).

**Trails.** Курируемые карты по теме, объединяющие evergreens разных полей. Живут в корневой `_trails/`, не внутри полей. Создаются, когда по теме копится 5+ кросс-полевых evergreens и LLM нужна компактная карта.

## Граница между evergreen и reflection

- Если формулировка нейтральна, переиспользуема и не привязана к личному контексту — это evergreen.
- Если формулировка субъективна, привязана к моменту автора и содержит план — это reflection.
- Смешение разрушает оба слоя. Lint поднимает такие случаи как «Ask».

## Wiki-ссылки

- Если фраза в тексте отличается от имени страницы — алиас: `[[Название страницы|текст в заметке]]`.
- Если фраза совпадает с именем страницы — простая ссылка: `[[Название страницы]]`.
- Связи всегда живут инлайн в прозе. Раздел «Связи» в конце страницы запрещён.
- Исключение: связь «родитель — потомок» при разложении источника на несколько концептов — упоминание остаётся в прозе, не в отдельной секции.

## Заголовки

H1 внутри файлов не используется — заголовок задаётся именем файла. Вся разметка тела начинается с H2.

## Язык

Не используй англицизмы. Заменяй на русские термины. Исключения: устойчивые англоязычные выражения, вошедшие в русский язык; собственные имена; технические идентификаторы (LLM, RAG, имена файлов и продуктов); оригинальные цитаты на английском.

## Логирование

Все операции скиллов оставляют запись в `log.md` в корне vault. Журнал append-only — старые записи не правятся.

### Конвенция заголовка

```
## [YYYY-MM-DD] <op> | <subject>
```

Где `<op>` — одно из:

- `ingest` — обработка нового источника (`Forest-process-observation`).
- `init` — создание нового поля (`Forest-initialize-field`).
- `reflection` — создание рефлексии (`Forest-reflection`).
- `lint` — проход lint (`Forest-lint`).
- `refactor` — структурное изменение, не привязанное к одной операции (вручную или после lint-разбора).

`<subject>` — название источника / имя поля / имя рефлексии / scope lint.

### Тело записи

Под заголовком — пустая строка, затем маркированный список затронутых файлов с краткой сутью изменений в каждом:

```
- **<путь к файлу>** — что сделано.
- **<следующий файл>** — что сделано.
```

Для записей lint — сводка по уровням (auto-fix / ask / report), без копирования полного отчёта.

Если запись связана с предыдущим состоянием vault или предыдущей операцией, упомяни это в первом-втором абзаце перед списком файлов: контекст помогает читать журнал спустя время.

### Что в лог не пишется

- Чтения без изменений.
- Промежуточные ревизии одной операции (только итог).
- Личное содержание рефлексий (только факт создания и связей).

## Frontmatter — единый формат

Каждый слой имеет свой `type:`:

- `type: observation` — для файлов в `observations/`.
- `type: evergreen` — для файлов в `evergreens/`.
- `type: reflection` — для файлов в `reflections/`.
- `type: field` — для `FIELD.md` в корне поля.
- `type: trail` — для файлов в корневой `_trails/`.

Полные шаблоны frontmatter — в `_schemas/templates/`.

## Скиллы

В `_schemas/skills/` лежат инструкции:

- **`Forest-process-observation.md`** — найти необработанные источники и интегрировать в evergreens + кросс-полевые ссылки.
- **`Forest-initialize-field.md`** — создать новое поле или превратить существующую папку в поле.
- **`Forest-reflection.md`** — преобразовать пользовательский текст/транскрипцию в файл reflection с заземлением на evergreens.
- **`Forest-lint.md`** — проход по vault на структурную целостность.

Каждый скилл во время прохода читает только то, что ему разрешено в собственном разделе «Область чтения». Прочие правила-файлы не загружаются — модель опирается на этот `CLAUDE.md` и на свой скилл.
